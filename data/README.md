# Data

| File | What it is |
|---|---|
| `medicines.json` | **The database the finder uses.** 2,439 Jan Aushadhi products; 1,786 have matched brands (up to 20 example brands each, 26,763 in total). **Generated by `python -m medperplexity build`** from the two raw CSVs. |
| `jan_aushadhi.csv` | Raw input 1: the official Jan Aushadhi (PMBJP) product list (drug code, generic name, unit size, MRP, group). |
| `brand_medicines.csv` | Raw input 2 (**not in the repo**, 57 MB, 273,929 rows): brand name, MRP, pack, manufacturer, salt composition, image URL. Needed only to rebuild. |

## Rebuilding the database

```bash
# put brand_medicines.csv in data/ (it is git-ignored; use Git LFS if you want to track it)
python -m medperplexity build                                   # defaults: data/*.csv -> data/medicines.json
python -m medperplexity build --max-brands 50 -o data/big.json  # keep more example brands per product
```

Takes about 8 seconds. The pipeline lives in `src/medperplexity/build_database.py`, followed
automatically by the cleaning rules in `data_cleaning.py`.

### How a brand is matched to a Jan Aushadhi product

A branded medicine counts as a match only if **all four** hold:

1. **Same active ingredients.** The set of ingredient words is identical after normalising spelling
   (Amoxycillin = Amoxicillin, Aciclovir = Acyclovir ...) and ignoring salt words (hydrochloride, sodium ...).
   Catalogue typos such as "Tazobactum" are repaired by a strict nearest-spelling step.
2. **Same strengths**, after unit conversion (500 mcg = 0.5 mg). Concentrations like `(2mg per ml)` are
   not mistaken for extra ingredients.
3. **Same dosage form and release type**: tablet, capsule, injection, oral liquid, cream ...; plain vs
   modified-release (SR/ER/XL), dispersible, chewable, sublingual.
4. **Comparable pack size**: within 4x of the Jan Aushadhi pack, priced **per unit** (per tablet / ml / gram).

`market_avg_price` is the **median** brand price per unit, scaled to the Jan Aushadhi pack, so
`jan_price` and `market_avg_price` always describe the same quantity of medicine.
The example brands stored are those from the largest manufacturers (the ones people search for), then closest to the median price.

### Record schema

```json
{
  "generic_name": "Atorvastatin Tablets IP 10mg",
  "jan_price": 8.25,
  "unit_size": "10's",
  "common_brands": ["Atorlip 10 Tablet", "..."],
  "found_match": true,
  "market_avg_price": 50.0,
  "matched_brand_count": 31,
  "savings_alert": "Save ₹41 (83%)",
  "savings_percentage": "83%"
}
```

Unmatched products have `found_match: false`, an empty `common_brands`, and no `market_avg_price`.
`matched_brand_count` is the number of brands that matched in the full catalogue (usually far more than
the 20 stored).

## Why this replaced the original database

The first version of the database came from an embedding pipeline (S-PubMedBert sentence vectors plus rule-based
validation; see [`scripts/legacy/`](../scripts/legacy/README.md)). Comparing its output with the CSVs showed:

* **Prices were biased upward.** It kept only brands *more expensive* than the Jan Aushadhi price and averaged the five
  most expensive. All stored brands cost more than the generic, and the stored market price was typically **1.27x** the
  median brand price (median claimed saving 76% vs 69% now).
* Brands were chosen by **name-based** form and number checks that ignored pack size and release type. Only **57%** of
  its 8,628 brand assignments pass the same-ingredient / same-strength / same-form check above. Examples: a baby diaper
  matched a Rivastigmine capsule, a malaria test kit matched a typhoid vaccine, a plain Ropinirole tablet was paired
  with extended-release brands.
* **34% of price comparisons used different pack sizes** (e.g. 10 capsules vs a strip of 30).
* The government CSV has no MRP (0.0) for **387** products; the old file showed 324 of them as
  "Save ₹X (100%)". They are now `"Price Unavailable"`.

The rebuild therefore matches fewer products (1,786 vs 2,042) but they are correct matches, and the prices are fair.
Of the 1,786, 1,511 have a computed saving (median **69%**), 14 show no saving, and the rest have no usable Jan Aushadhi
price. The trade-off: the embedding model generalises better to unusual spellings, while `build_database.py` is
deterministic, needs no GPU and runs in seconds. A hybrid (embeddings to find candidates, the strict checks to decide)
is the natural next step.

`data_cleaning.py` still runs on every build: typo fixes (`Inection`, `Hydrchloride`, `Tabelts` ...),
clearing brands from the 260 surgical/consumable items (whole-word matching: `Set` no longer matches
Ondan**set**ron), and consistent savings text. It can also be run on its own:
`python -m medperplexity clean old.json -o data/medicines.json`.

## Known limits

* Only 20 example brands per product are stored (the catalogue has a median of 27 matches per product, and
  some have over 2,000). A brand outside the stored sample is not found by name (the generic name still is).
  Build with a larger `--max-brands` for local use, ideally with `rapidfuzz` installed.
* About 650 Jan Aushadhi products (devices, consumables, diagnostics, nutrition products, unusual
  formulations) have no equivalent brand in the catalogue.
* Matching depends on the catalogue's own salt text; combination packs, kits and unusual units may be missed.
